02  Principles

Small files, honest labels, no service.

i.

Plain files in Git

One YAML record per file under .alethic/. They show up in pull requests and merge like code. No account, database, or network access.

ii.

Anchored to code

Records fingerprint the files they describe. When that code changes, the record is flagged may be stale, and it survives squash merges and rebases.

iii.

Honest trust

Agent claims are marked unverified. A human confirmation is an attribution tied to the exact text, never shown as authenticated approval.

iv.

Agent-neutral

A CLI any agent can run, short blocks for AGENTS.md, CLAUDE.md, and GEMINI.md, and an MCP server.

03  How it works

Three commands carry the work across sessions.

  1. 01

    Set up

    Create .alethic/ and tell agents to start from a briefing.

    alethic init alethic render agents-md --write
  2. 02

    Leave a checkpoint

    Before stopping, record what failed, what ran, and the next safe step.

    alethic receipt run -- npm test alethic checkpoint create \ --failed "Delete session rows::cache still serves them" \ --next "Compare a token version on refresh"
  3. 03

    Resume anywhere

    A fresh session, any agent, compiles a cited briefing within a budget.

    alethic resume --budget 2500 alethic validate
